## 트리는 부모와 자식 관계로 계층을 표현한다

트리는 값을 가지는 노드와 노드를 연결하는 간선으로 이루어진다. 가장 위에 있는 노드를 루트라고 한다. 루트에서 아래로 연결된 노드는 자식이고 자식을 가리키는 노드는 부모다. 같은 부모를 둔 노드는 형제다.

오늘의 공통 예제에서는 `A`가 루트다. `A`의 자식은 `B`와 `C`이고 `B`와 `C`는 형제다. `B`의 자식은 `D`와 `E`다. `C`는 왼쪽 자식 없이 오른쪽 자식 `F`만 가진다. 자식이 없는 `D`, `E`, `F`는 리프 노드다. `B`와 그 자손인 `D`, `E`를 묶으면 `B`를 루트로 하는 서브트리가 된다.

깊이는 루트에서 특정 노드까지 지나온 간선 수다. 이 글에서는 루트의 깊이를 `0`으로 둔다. 따라서 `A`의 깊이는 `0`, `B`와 `C`의 깊이는 `1`, `D`와 `E`와 `F`의 깊이는 `2`다. 레벨도 깊이와 같은 번호를 사용한다. 자료에 따라 루트를 레벨 `1`로 세는 경우가 있지만 여기서는 레벨의 시작도 `0`으로 통일했다.

높이는 트리에서 가장 깊은 노드의 깊이다. 공통 예제의 높이는 `2`다. 깊이와 높이를 노드 수로 세면 안 된다. 루트에서 `A`를 거쳐 `F`로 가는 경로는 `A → C → F`이고 경로의 길이는 노드 세 개가 아니라 간선 두 개다. OpenDSA도 경로의 길이를 연결된 간선 수로 설명하고 깊이와 높이를 이 기준으로 정의한다.

비어 있지 않은 트리의 노드가 `n`개라면 간선은 `n - 1`개다. 루트에는 부모로 들어오는 간선이 없고 나머지 노드는 각자 하나의 부모 간선을 가지기 때문이다. 이 관계를 기준으로 노드 수와 간선 수를 함께 확인하면 트리의 기본 구조를 점검할 수 있다.

## 이진 트리는 자식이 최대 두 개다

일반 트리는 한 노드가 가질 수 있는 자식 수에 제한이 없다. 반면 이진 트리는 각 노드가 왼쪽 자식과 오른쪽 자식을 최대 하나씩 가진다. 왼쪽과 오른쪽은 단순히 자식의 개수가 아니라 서로 구분되는 위치다.

따라서 자식이 하나인 노드도 이진 트리에 포함된다. 왼쪽 자식만 있는 노드와 오른쪽 자식만 있는 노드는 모두 조건을 만족하지만 구조는 서로 다르다. 모든 노드가 두 자식을 가져야 한다고 설명하면 이진 트리와 정이진 트리를 섞게 된다.

정리하면 이진 트리의 조건은 자식 수의 최댓값이다. 자식이 `0`개인 리프도 이진 트리의 노드이고 자식이 `1`개인 노드도 이진 트리의 노드다. 자식이 `2`개라면 왼쪽과 오른쪽 자리를 모두 사용한다.

## 정이진 트리와 완전 이진 트리 및 포화 이진 트리

세 종류를 이름으로 외우기보다 자식 수와 레벨의 채움 조건으로 나누어 보았다.

- 정이진 트리(`Full Binary Tree`): 각 노드의 자식 수가 `0`개 또는 `2`개다. 자식이 `1`개인 노드가 하나라도 있으면 정이진 트리가 아니다.
- 완전 이진 트리(`Complete Binary Tree`): 마지막 레벨을 제외한 모든 레벨이 채워져 있고 마지막 레벨은 왼쪽부터 빈틈없이 채워져 있다.
- 포화 이진 트리(`Perfect Binary Tree`): 모든 레벨이 가득 차 있다. 모든 내부 노드가 두 자식을 가지고 모든 리프의 깊이가 같다.

처음에는 정이진 트리면 모양이 고르게 채워져 있을 것이라고 생각했다. 하지만 자식 수가 `0`개 또는 `2`개라는 조건만으로는 마지막 레벨의 위치를 제한하지 않는다. 그래서 정이진 트리라는 사실만으로 완전 이진 트리라고 판단할 수 없다.

반대로 완전 이진 트리도 정이진 트리 조건을 반드시 만족하지 않는다. 마지막 레벨을 왼쪽부터 채웠더라도 어떤 내부 노드가 자식 하나만 가질 수 있기 때문이다. 특히 마지막 레벨에 노드가 있다는 설명만으로는 부족하다. 그 노드들이 왼쪽부터 채워졌는지까지 확인해야 한다.

자료에 따라 `full`과 `complete`라는 영문 용어를 다르게 옮기는 경우가 있으므로 이 글에서는 위 조건으로 통일한다. 포화 이진 트리는 정이진 조건과 완전 조건을 모두 만족하는 예다. 세 조건은 서로 배타적인 분류가 아니라 구조 조건이 누적될 수 있는 관계다.

## 배열로 트리를 표현하면 위치 관계를 계산한다

트리를 배열에 넣을 때는 순회 결과를 차례대로 나열하는 것이 아니다. 트리에서의 위치 관계를 인덱스로 표현한다. 0번 인덱스를 루트로 사용하는 이진 트리에서는 인덱스 `i`의 관계를 다음처럼 계산한다.

- 왼쪽 자식: `2i + 1`
- 오른쪽 자식: `2i + 2`
- 부모: `(i - 1) / 2`의 정수 나눗셈

부모 계산은 루트를 제외한 노드에 적용한다. 루트인 인덱스 `0`에는 부모가 없기 때문이다. Java에서 정수끼리 나누면 소수점 아래가 버려지므로 `(i - 1) / 2`를 정수 나눗셈으로 사용할 수 있다.

공통 예제를 배열로 옮기면 다음과 같다.

```text
인덱스: 0  1  2  3  4  5     6
값:     A  B  C  D  E  null   F
```

`A`의 왼쪽 자식 `B`는 인덱스 `1`, 오른쪽 자식 `C`는 인덱스 `2`에 놓인다. `B`의 자식 `D`와 `E`는 인덱스 `3`과 `4`다. `C`의 왼쪽 자식이 없더라도 그 자리를 건너뛰고 `F`를 당겨 담으면 안 된다. 오른쪽 자식의 위치인 인덱스 `6`을 유지하려면 인덱스 `5`를 비워 두어야 한다.

그래서 노드는 `6`개지만 `F`의 인덱스는 `6`이다. 이 위치 규칙을 유지하려면 최소 배열 길이는 `7`이다. 노드 수와 필요한 배열 길이가 항상 같지는 않다. 완전 이진 트리는 빈칸이 적어 배열 표현에 잘 맞고 편향되거나 중간 빈자리가 많은 트리는 배열 공간을 낭비할 수 있다.

```java
String[] tree = {"A", "B", "C", "D", "E", null, "F"};

int parentIndex = 2;
int rightIndex = 2 * parentIndex + 2;

System.out.println(rightIndex);      // 6
System.out.println(tree[rightIndex]); // F
System.out.println(tree.length);     // 7
```

이 코드에서 배열의 `null`은 C의 왼쪽 자식 자리가 비어 있다는 표시다. 순회 결과가 `A B C D E F`라는 이유로 그 순서대로 배열에 저장한 것이 아니다. 위치 관계를 계산하기 위해 빈 슬롯을 포함한 것이다.

## 연결 방식은 자식 노드를 참조한다

연결 방식에서는 이진 트리의 노드를 데이터와 왼쪽 및 오른쪽 자식 참조로 표현할 수 있다. 자식이 없는 방향은 `null`로 둔다. 배열 인덱스를 맞추려고 빈 자리에 노드 객체를 만들 필요가 없다.

```java
class Node {
    String value;
    Node left;
    Node right;

    Node(String value) {
        this.value = value;
    }
}

Node c = new Node("C");
c.right = new Node("F");
// c.left는 null
```

이 코드는 사용자 정의 노드의 개념 예제다. Java 표준 라이브러리가 제공하는 `Tree` 클래스의 사용법을 보여 주는 코드는 아니다. `c.left`는 참조가 `null`이라 왼쪽 자식이 없고 `c.right`는 `F` 노드를 가리킨다.

Java의 참조를 물리 메모리 주소나 가상 주소 숫자라고 단정해서는 안 된다. 여기서 중요한 것은 노드가 다른 노드를 참조해 관계를 표현한다는 점이다. 노드들이 메모리에 붙어 있어야 연결되는 것도 아니다.

일반 트리처럼 자식 수가 제한되지 않는다면 자식들을 목록으로 관리할 수 있다. 이진 트리의 `left`와 `right` 필드만으로 모든 계층 구조를 표현하려고 하면 자식 수가 세 개 이상인 노드를 담기 어렵다.

배열과 연결 방식의 차이를 같은 A~F 트리로 비교하면 다음과 같다. 배열은 위치와 빈 슬롯을 보존하고 연결 방식은 실제 자식이 있는 방향만 참조한다.

## 순회는 현재 노드를 처리하는 시점이 다르다

순회는 트리의 모든 노드를 정해진 순서로 한 번씩 처리하는 방법이다. 같은 A~F 트리를 사용해 현재 노드를 언제 처리하는지 비교했다.

전위 순회는 현재 노드를 먼저 처리한 뒤 왼쪽 서브트리와 오른쪽 서브트리를 처리한다.

```text
현재 노드 → 왼쪽 서브트리 → 오른쪽 서브트리
결과: A B D E C F
```

중위 순회는 왼쪽 서브트리 전체를 처리하고 현재 노드를 처리한 뒤 오른쪽 서브트리 전체를 처리한다.

```text
왼쪽 서브트리 → 현재 노드 → 오른쪽 서브트리
결과: D B E A C F
```

중위 순회에서 `B`만 먼저 읽는다고 생각하면 안 된다. `B`를 루트로 하는 왼쪽 서브트리인 `D`를 먼저 처리하고 `B`를 처리한 다음 `E`를 처리한다. 그 서브트리 전체가 끝난 뒤에야 `A`를 처리한다.

후위 순회는 왼쪽 서브트리와 오른쪽 서브트리를 모두 처리한 뒤 현재 노드를 처리한다.

```text
왼쪽 서브트리 → 오른쪽 서브트리 → 현재 노드
결과: D E B F C A
```

레벨 순회는 위 레벨부터 같은 레벨의 왼쪽 노드 순서대로 방문한다.

```text
위 레벨 → 같은 레벨의 왼쪽 노드부터
결과: A B C D E F
```

“왼쪽부터 읽는다”는 표현만으로는 순회를 설명할 수 없다. 전위·중위·후위 순회는 모두 왼쪽 서브트리를 먼저 보지만 현재 노드를 처리하는 시점이 다르다. 레벨 순회는 서브트리 내부로 끝까지 내려가는 대신 같은 깊이의 노드를 묶어 처리한다.

오늘 예제는 순회 순서를 확인하기 위한 일반 이진 트리다. 중위 순회 결과가 모든 이진 트리에서 정렬된 값이 되는 것은 아니다. 이진 탐색 트리처럼 값의 정렬 규칙을 함께 가진 구조에서만 중위 순회와 정렬 순서를 연결할 수 있다.

## 전체 순회와 탐색 비용은 나누어 본다

노드가 `n`개인 트리를 전위·중위·후위 또는 레벨 순회로 모두 방문하면 각 노드를 한 번씩 처리하므로 시간 복잡도는 `O(n)`이다. 방문 순서는 다르지만 처리하는 노드 수는 같다.

특정 값을 찾는 비용은 순회 비용과 같은 방식으로 설명하면 안 된다. 일반 이진 트리는 왼쪽과 오른쪽 중 어느 방향에 원하는 값이 있는지 판단할 정렬 규칙이 없다. 따라서 최악의 경우 값을 찾기 위해 모든 노드를 확인해야 하고 시간 복잡도는 `O(n)`이다.

트리가 두 갈래로 나뉜다는 사실만으로 탐색을 `O(log n)`이라고 할 수 없다. 한쪽으로만 이어진 편향 트리라면 루트에서 가장 아래 노드까지 `n - 1`개의 간선을 따라갈 수 있다. 이 경로를 확인하는 비용도 `O(n)`이다. 균형이나 값의 정렬 규칙을 확인하지 않고 트리라는 모양만 보고 `O(log n)`이라고 판단하면 안 된다.

이진 탐색 트리의 삽입·삭제 규칙과 균형 트리 구현은 다음 학습 범위로 남겼다. 오늘은 일반 이진 트리에서 전체 순회와 특정 경로 탐색의 비용을 나누어 설명하는 데 집중했다.

## 백엔드의 계층 데이터와 트리 선택

백엔드에서는 카테고리나 조직 구조처럼 부모와 자식 관계를 가진 데이터를 만날 수 있다. 카테고리 아래에 하위 카테고리가 여러 개 생길 수 있다면 자식 수가 두 개로 제한되지 않는다.

계층 데이터라는 이유만으로 이진 트리를 선택하지는 않는다. 자식 수와 데이터의 형태를 보고 일반 트리처럼 자식 목록을 둘지, 자식이 최대 두 개인 이진 트리로 표현할지 결정해야 한다. 오늘은 이를 실제 엔티티로 구현하거나 SQL로 조회한 경험을 정리한 것이 아니라 자료구조를 선택할 때 확인할 조건으로만 연결했다.

## 오늘의 정리

트리는 노드와 간선으로 부모와 자식 관계를 표현하는 계층 구조다. 이진 트리는 자식이 최대 두 개라는 제약을 가진 트리의 한 형태이며 자식이 하나인 노드도 포함한다. 정이진 트리와 완전 이진 트리와 포화 이진 트리는 이름보다 자식 수와 레벨의 채움 조건을 확인해야 구분할 수 있다.

배열 표현에서는 노드의 위치를 인덱스 규칙으로 계산한다. 그래서 오른쪽 자식만 있는 경우에도 왼쪽 자리를 비워야 하고 노드 수와 필요한 배열 길이가 달라질 수 있다. 연결 표현에서는 자식 노드 참조로 관계를 만들기 때문에 자식이 없는 방향에 별도 노드 객체를 만들지 않는다. 자식 수가 제한되지 않는 일반 트리는 자식 목록을 사용하는 편이 구조에 맞다.

순회는 같은 트리라도 현재 노드를 처리하는 시점에 따라 결과가 달라진다. 전위·중위·후위·레벨 순회는 모두 전체 방문 비용이 `O(n)`이지만 특정 값의 탐색은 일반 이진 트리에서 최악 `O(n)`이다. 트리라는 모양만으로 탐색을 `O(log n)`이라고 판단할 수 없다는 점도 함께 정리했다.

자료구조를 고를 때는 자식 수와 데이터 형태 그리고 수행할 작업을 함께 봐야 한다. 다음에는 값의 정렬 규칙을 가진 이진 탐색 트리로 범위를 넓혀 보려고 한다.
