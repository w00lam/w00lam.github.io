HTTP와 HTTPS를 함께 정리하면 요청과 응답의 구성, 무상태 특성, 통신 보안이 한꺼번에 섞여 보였다. HTTP는 웹 데이터를 주고받는 애플리케이션 계층 프로토콜이고 HTTPS는 그 통신을 TLS로 보호하는 방식이다. 오늘은 HTTP 메시지의 구조와 무상태 특성을 나누고 HTTPS에서 공개키와 대칭키가 맡는 역할까지 정리했다.

오늘 글에서는 다음 질문에 답해 본다.

- HTTP 요청과 응답에는 어떤 정보가 들어가는가?
- 무상태 특성과 요청·응답 메시지의 구성은 어떻게 다른가?
- HTTPS는 HTTP 통신을 어떤 보안 목적에 따라 보호하는가?
- HTTPS에서 공개키 기반 기능과 대칭키 데이터 보호는 어떤 관계인가?

## 1. HTTP는 요청과 응답으로 웹 데이터를 주고받는다

HTTP는 클라이언트와 서버가 웹 데이터를 요청과 응답으로 주고받는 애플리케이션 계층 프로토콜이다. 클라이언트가 요청을 보내면 서버가 응답을 돌려주는 구조로 통신한다.

요청에는 메서드와 경로, 헤더가 들어가고 필요한 경우 본문도 포함된다. 응답에는 상태 코드와 헤더가 들어가고 필요한 경우 본문이 포함된다.

| 구분 | 포함되는 정보 |
| --- | --- |
| 요청 | 메서드, 경로, 헤더, 필요한 경우 본문 |
| 응답 | 상태 코드, 헤더, 필요한 경우 본문 |

메시지 구성과 상태 유지는 서로 다른 기준이다. 요청에 메서드와 헤더가 들어가고 응답에 상태 코드가 들어간다는 설명은 한 번의 요청·응답 메시지가 어떤 형태인지에 관한 내용이다.

## 2. 무상태 특성과 메시지 구조를 구분하기

HTTP의 무상태 특성은 각 요청이 이전 요청의 상태를 자동으로 기억하거나 이어받지 않는다는 뜻이다. 이는 여러 요청 사이에서 상태를 어떻게 다루는지를 가리킨다.

반면 요청·응답 메시지의 구성은 한 번의 통신에 어떤 정보가 들어가는지를 설명한다. 요청에 메서드와 경로, 헤더, 필요에 따른 본문이 있고 응답에 상태 코드와 헤더, 필요에 따른 본문이 있다는 사실만으로 HTTP가 이전 요청의 상태를 기억한다고 볼 수는 없다.

메시지 구성은 요청과 응답 안의 정보를 기준으로 보고 무상태는 요청과 요청 사이의 상태 유지 여부를 기준으로 봐야 한다. 두 기준을 나누어야 HTTP 메시지의 형식과 요청 사이의 상태 관리가 섞이지 않는다.

## 3. HTTPS는 TLS로 HTTP 통신을 보호한다

HTTPS는 HTTP 통신을 TLS로 보호하는 방식이다. HTTPS가 제공하는 보안 목적은 서버 인증, 기밀성, 무결성으로 정리할 수 있다.

| 보안 목적 | 의미 |
| --- | --- |
| 서버 인증 | 통신 상대인 서버를 확인한다. |
| 기밀성 | 통신 내용을 보호한다. |
| 무결성 | 통신 내용이 바뀌지 않았는지 확인한다. |

공개키 기반 기능은 서버 인증과 통신에 사용할 대칭키를 설정하는 데 활용한다. 실제 HTTP 데이터는 공개키로 모두 암호화하는 것이 아니라 효율적인 대칭키로 보호한다. 공개키 기반 기능과 대칭키 데이터 보호는 역할이 다르므로 한 문장 안에서 구분해 설명해야 한다.

## 학습 과정에서 바뀐 이해

처음에는 HTTP 요청과 응답의 구성에 헤더와 본문이 들어간다는 설명과 무상태 특성을 같은 맥락으로 생각했다. 다시 정리하면서 요청·응답의 구성은 메시지 형식이고 무상태는 이전 요청의 상태를 자동으로 이어받지 않는 통신 특성이라는 점을 나누었다.

HTTPS는 공개키로 실제 HTTP 데이터를 암호화한다고 설명하려 했다. 하지만 공개키 기반 기능은 서버 인증과 통신용 대칭키 설정에 활용하고 실제 데이터는 효율적인 대칭키로 보호한다는 역할 구분으로 보완했다. 서버 인증, 기밀성, 무결성이라는 HTTPS의 보안 목적도 함께 정리했다.

## 오늘의 정리

- HTTP는 클라이언트와 서버가 웹 데이터를 요청과 응답으로 주고받는 애플리케이션 계층 프로토콜이다.
- 요청에는 메서드와 경로, 헤더, 필요한 경우 본문이 들어가고 응답에는 상태 코드와 헤더, 필요한 경우 본문이 들어간다.
- 무상태는 이전 요청의 상태를 자동으로 기억하거나 이어받지 않는 특성이며 메시지 구성과는 다른 개념이다.
- HTTPS는 TLS로 HTTP 통신을 보호하며 서버 인증, 기밀성, 무결성을 제공한다.
- 공개키 기반 기능은 서버 인증과 대칭키 설정에 활용하고 실제 데이터는 대칭키로 보호한다.

오늘은 HTTP 요청·응답의 구조와 HTTPS의 세 가지 보안 목적을 정리했다. 공개키 기반 인증·키 설정과 대칭키 데이터 보호를 한 문장으로 명확하게 설명하는 연습은 남아 있다. 무상태 특성을 메시지 구성과 구분해 말하는 것도 다시 답해 볼 과제로 남겼다.
