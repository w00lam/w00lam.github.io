[DFS/BFS와 LIS](/posts/dfs-bfs-lis/)를 정리할 때 그래프에서는 방문 순서가, 배열에서는 상태 배열의 의미가 중요하다는 점을 확인했다. DFS와 BFS는 정점을 방문하는 순서를 결정하고, BFS는 모든 간선의 가중치가 같을 때 가장 적은 간선 수의 경로를 찾는다.

이번에는 간선마다 비용이 다를 때 최단 거리를 구하는 Dijkstra와, 여러 boolean 상태를 하나의 정수로 관리하는 BitMask를 이어서 정리했다. 둘은 서로 다른 알고리즘이지만 현재 상태를 저장하고 다음 상태를 선택하는 기준이 분명하다는 공통점이 있다.

처음에는 다익스트라에서 시작 정점의 `dist[0]`을 계속 사용하려 했고, 비트마스크에서는 `1 << i`가 선택할 비트인지 상태를 바꾼 결과인지 구분하지 못했다. 작은 예제를 한 단계씩 확인하며 현재 정점과 선택 마스크의 역할을 나눴다. 아래 Java 코드는 학습한 핵심을 설명하는 예시이며, 전체 메서드를 독립적으로 작성하거나 컴파일·실행한 기록은 아니다.

## 1. 방문 순서에서 이동 비용과 상태 표현으로

DFS와 BFS는 그래프를 방문하는 순서를 정한다. DFS는 한 경로를 깊게 내려가고, BFS는 Queue에 들어온 정점을 가까운 순서대로 처리한다. 간선의 가중치가 모두 같다면 한 번 이동할 때 드는 비용도 같으므로 BFS의 레벨이 최단 이동 횟수로 이어진다.

간선마다 비용이 다르면 “먼저 도착한 경로”가 “가장 싼 경로”라는 보장이 없다. 필요한 값은 지금까지의 누적 비용이다. Dijkstra는 현재까지의 거리가 가장 짧은 정점을 먼저 선택하고, 그 정점을 거쳐 가는 비용이 더 작을 때만 거리를 갱신한다.

BitMask는 그래프의 이동 순서를 정하는 알고리즘은 아니다. 작은 고정 집합에서 각 원소의 포함 여부를 여러 boolean 값 대신 정수의 비트로 표현한다. DP에서 방문 집합 같은 상태를 저장하는 데도 쓸 수 있지만, 이번 글에서는 복잡한 비트마스크 DP로 확장하지 않고 기본 연산과 자료구조 선택까지만 다룬다.

## 2. Dijkstra — 누적 비용이 가장 작은 경로를 먼저 확인한다

### 2.1 작은 간선이 아니라 누적 거리를 비교한다

집에서 회사로 가는 두 경로가 있다.

```text
집 → A: 1
A → 회사: 2
집 → B: 4
B → 회사: 1
```

집에서 A를 거쳐 회사로 가면 비용은 `1 + 2 = 3`이다. B를 거치면 `4 + 1 = 5`가 된다. 첫 번째 간선만 보면 집에서 A로 가는 1이 가장 작다. 하지만 비교 대상은 시작점부터 현재 경로까지 더한 누적 비용이다.

다익스트라는 정점에 도착하는 간선 하나의 가중치만 보고 다음 정점을 고르지 않는다. 시작 정점에서 그 정점까지 알려진 거리 중 가장 작은 값을 가진 정점을 고른다. 이 예제에서는 A를 거친 회사까지의 거리 3이 B를 거친 거리 5보다 짧으므로 A 경로를 최단 경로 후보로 유지한다.

### 2.2 거리 배열은 0과 INF를 구분해 초기화한다

거리 배열에는 시작 정점에서 각 정점까지 현재까지 알고 있는 최단 거리 후보를 저장한다.

```java
Arrays.fill(dist, Integer.MAX_VALUE);
dist[start] = 0;
```

시작 정점의 거리는 자기 자신까지 이동하지 않으므로 0이다. 나머지는 아직 경로를 발견하지 못했다는 뜻으로 `INF`를 사용한다. 실제 Java 코드에서는 `Integer.MAX_VALUE`를 INF처럼 사용할 수 있지만, 실제 거리 0인 정점과는 다른 상태다.

`Integer.MAX_VALUE`에 가중치를 바로 더하면 정수 오버플로가 발생할 수 있다. 현재 정점이 도달 가능한지 확인하거나, 거리와 가중치의 범위가 크다면 `long`과 충분히 작은 INF를 사용해 덧셈 범위를 관리한다. 학습 예제처럼 큐에 도달 가능한 정점만 넣는 경우에도 실제 입력에서는 가중치 범위를 확인한다.

### 2.3 간선 완화는 더 짧을 때만 갱신한다

현재 정점 `current`에서 다음 정점 `next`로 이동하는 새 비용을 기존 거리와 비교한다.

```java
if (dist[current] + weight < dist[next]) {
    dist[next] = dist[current] + weight;
}
```

이 과정을 간선 완화라고 한다. 새 경로가 더 짧을 때만 `dist[next]`를 바꾼다. 두 값이 같다면 최단 거리 값은 이미 같으므로 반드시 갱신할 필요가 없다.

학습 중에는 현재 정점에서 출발하면서도 `dist[0]`을 사용하려고 했다. 시작 정점이 0인 작은 예제에서는 우연히 맞아 보이지만, 정점 1이나 2를 처리하는 순간 잘못된 값이 된다. 현재 정점에서 다음 정점으로 이동하는 비용은 항상 `dist[current] + weight`로 계산한다.

시각화에는 다음 그래프를 사용한다.

```text
0 → 1 (2)
0 → 2 (5)
1 → 3 (1)
2 → 3 (2)
```

시작 정점은 0이고 초기 거리는 `[0, INF, INF, INF]`다. 0에서 1로 가는 비용은 `2`, 0에서 2로 가는 비용은 `5`다. 정점 1을 거쳐 3으로 이동하면 `2 + 1 = 3`이므로 `dist[3]`이 `3`으로 갱신된다. 정점 2에서 3으로 가는 비용은 `5 + 2 = 7`이라 기존 `3`을 유지한다.

### 2.4 음수 가중치가 있으면 정확성을 보장할 수 없다

다음 방향 그래프로 확인해 보자.

```text
A → B: 2
A → C: 5
C → B: -4
```

A에서 B로 바로 가면 비용은 2다. 하지만 C를 거치면 `5 + (-4) = 1`이므로 더 짧다.

다익스트라가 현재 가장 작은 거리의 정점을 꺼냈을 때 그 값이 최단 거리로 확정된다고 보는 이유는, 이후에 확인할 간선이 음수가 아니라는 전제가 있기 때문이다. 음수 간선이 있으면 나중에 다른 경로를 거쳐 더 짧은 값이 나타날 수 있다. 음수 간선이 있다고 해서 항상 틀리는 것은 아니지만, 일반적인 다익스트라만으로는 정확성을 보장하기 어렵다.

### 2.5 희소 그래프에서는 인접 리스트와 우선순위 큐를 함께 사용한다

인접 행렬은 `graph[u][v]`처럼 두 정점 사이의 간선을 바로 조회한다. 정점이 `V`개라면 `V × V` 공간이 필요하므로 간선이 적은 희소 그래프에서는 빈 칸이 늘어난다.

인접 리스트는 각 정점에 실제로 연결된 간선만 저장한다.

```text
A: [(B, 3), (C, 5)]
B: [(C, 2)]
C: []
```

이 구조에서는 현재 정점에서 이어지는 간선만 순회한다. 여기에 우선순위 큐를 사용하면 아직 처리하지 않은 정점 중 누적 거리가 가장 작은 항목을 먼저 꺼낸다. Java `PriorityQueue<int[]>`에 `{정점 번호, 거리}` 형태를 저장한다면 비교 기준은 정점 번호가 아니라 거리인 `node[1]`이어야 한다.

```java
PriorityQueue<int[]> pq = new PriorityQueue<>(
    Comparator.comparingInt(node -> node[1])
);

pq.offer(new int[]{start, 0});
```

Java `PriorityQueue`는 같은 우선순위 항목의 순서를 보장하지 않는다. 시각화에서는 동일한 거리가 나올 때 정점 번호가 작은 항목을 먼저 보여 일관성을 유지했다. 실제 알고리즘에서 중요한 기준은 거리이고, 정점 번호 순서는 이해를 돕는 추가 기준이다.

### 2.6 오래된 큐 항목은 다시 처리하지 않는다

거리 값을 갱신할 때 기존 큐 항목을 제거하지 않고 새 항목을 추가하는 구현도 있다. 이 경우 같은 정점의 오래된 거리와 새 거리가 큐에 함께 남는다.

예를 들어 큐에 `(A, 8)`이 남아 있는데 이미 `dist[A] = 4`로 줄었다면, `(A, 8)`은 현재 최단 거리 정보가 아니다. 이때는 다음 조건으로 건너뛴다.

```java
int[] node = pq.poll();
int current = node[0];
int currentDist = node[1];

if (currentDist > dist[current]) {
    continue;
}
```

큐에서 꺼낸 값과 `dist[current]`가 같다면 유효한 항목이다. 반대로 큐의 값이 더 크면 이미 더 짧은 경로를 찾았다는 뜻이라 `continue`로 현재 반복만 끝낸다. `continue`는 전체 `while`문을 종료하지 않고 다음 큐 항목으로 넘어간다.

### 2.7 시간 복잡도는 그래프 표현과 선택 방식에 따라 달라진다

학습한 두 방식을 비교하면 아래와 같다.

| 방식 | 시간 복잡도 | 그래프 저장 공간 |
| --- | --- | --- |
| 인접 행렬 + 선형 탐색 | `O(V²)` | `O(V²)` |
| 인접 리스트 + 우선순위 큐 | 일반적인 단순 그래프에서 `O((V + E) log V)` | `O(V + E)` |

`V`는 정점 수이고 `E`는 간선 수다. Java `PriorityQueue`에 갱신 항목을 중복해서 넣는 구현에서는 큐의 항목 수까지 고려해 상한을 `O((V + E) log(V + E))`로 설명한다.

희소 그래프는 `E`가 `V²`보다 훨씬 작다. 인접 행렬은 연결되지 않은 정점까지 확인하지만 인접 리스트는 실제 간선만 순회한다. 우선순위 큐가 다음 정점을 고르는 비용도 줄이므로 저장 공간과 탐색 비용을 함께 보면 인접 리스트 조합이 적합하다.

## 3. BitMask — 정수 하나에 여러 상태를 담는다

### 3.1 비트 인덱스는 오른쪽부터 0으로 센다

비트는 0 또는 1로 표현하며, 인덱스는 이진수의 오른쪽 자리부터 0으로 센다.

```text
인덱스: 3 2 1 0
비트:   0 1 0 1
```

이 상태는 인덱스 `{0, 2}`가 포함된 집합이고, 10진수로는 `5`다. 인덱스 0의 가중치는 `2⁰`, 인덱스 1은 `2¹`처럼 오른쪽에서 왼쪽으로 갈수록 두 배가 된다.

예를 들어 `1010`에서 켜진 비트는 왼쪽부터 세는 0과 2가 아니라 오른쪽 기준 인덱스 1과 3이다. 이 기준이 흔들리면 이후의 `1 << i` 계산도 모두 반대로 해석하게 된다.

### 3.2 연산자는 비트별 역할이 다르다

| 연산자 | 의미 |
| --- | --- |
| `&` | 두 비트가 모두 1일 때 1 |
| `\|` | 하나 이상이 1이면 1 |
| `^` | 두 비트가 서로 다를 때 1 |
| `~` | 각 비트를 반전 |
| `<<`, `>>` | 비트를 왼쪽 또는 오른쪽으로 이동 |

4비트 예시에서 `1010 & 1100`은 `1000`, `1101 ^ 1010`은 `0111`이다. `0010 << 1`은 `0100`이고 `1010 >> 1`은 `0101`이다.

Java `int`에서 `~`는 그려 놓은 4비트만 반전하지 않는다. 32비트 전체에 적용되므로 `~1100`을 4비트 예시의 `0011`과 같은 실제 `int` 값으로 생각하면 안 된다. 시각화에서는 이해를 위해 4비트만 표시하고, 본문에서는 Java의 고정 폭을 구분해 설명했다.

### 3.3 `1 << i`는 상태가 아니라 선택 마스크다

특정 인덱스를 고를 때는 다음 식을 사용한다.

```java
int flag = 1 << i;
```

`i = 2`라면 `flag`는 `0100`이다. 이 값은 기존 `mask`를 바꾼 결과가 아니라, 어느 비트를 조작할지 표시하는 선택 마스크다.

예를 들어 현재 상태가 `0001`이고 인덱스 1을 추가한다면 `1 << 1`의 결과인 `0010`을 만든 뒤 기존 상태에 OR 연산을 적용한다.

```text
0001 | 0010 = 0011
```

처음에는 `0010`을 최종 결과로 생각했지만, 선택할 비트의 표시와 변경된 전체 상태는 서로 다르다.

### 3.4 추가·삭제·확인·반전은 서로 다른 연산이다

```java
int flag = 1 << i;

mask |= flag;                       // 추가
mask &= ~flag;                      // 삭제
boolean exists = (mask & flag) != 0; // 확인
mask ^= flag;                       // 반전
mask = 0;                           // 전체 초기화
```

추가할 때는 OR로 선택한 비트를 1로 만든다. 이미 1인 비트는 그대로 유지한다. 삭제는 `~flag`로 선택 비트만 0인 마스크를 만든 뒤 AND한다. 다른 비트는 보존하면서 선택한 비트만 끄는 방식이다.

처음 작성한 `mask |= (0 << i)`는 삭제가 아니다. `0 << i`는 언제나 0이고, 기존 값에 0을 OR해도 상태가 달라지지 않는다. 삭제식은 `mask &= ~(1 << i)` 형태여야 한다.

확인은 상태를 바꾸지 않는다. `mask & flag`가 0이 아니면 해당 비트가 켜져 있다는 뜻이다. 이 표현식은 이번 학습에서 직접 작성해 완성한 식이다.

반전은 XOR를 사용한다. 켜져 있으면 끄고 꺼져 있으면 켠다. AND는 선택한 비트를 확인하거나 삭제할 때 사용할 수 있지만, 토글을 대신하지는 않는다.

*그림 2. BitMask 시각화는 인덱스를 선택해 연산하고, 연산 전·후 상태와 Java 표현식을 이력으로 남긴다.*

시각화의 `이전` 버튼은 해당 시점의 `mask`와 설명을 복원한다. 이전 단계로 이동한 뒤 새 연산을 실행하면 현재 위치 뒤의 이력을 제거하고 새 상태를 이어 간다. `초기화` 버튼은 연산 이력 전체를 처음 상태로 돌리고, `전체 초기화` 연산은 이력에 `mask = 0`을 추가한다. 두 동작은 서로 다르다.

### 3.5 단일 비트 연산은 `O(1)`이지만 모든 부분집합은 줄지 않는다

고정 폭 정수는 비트 하나를 켜거나 끄거나 확인하는 일을 일정한 수의 연산으로 처리하므로 `O(1)`이다. `int` 하나를 저장하는 공간도 `O(1)`으로 본다.

원소가 `n`개인 집합의 모든 부분집합을 확인하면 상태 수는 `2ⁿ`개다. 비트마스크는 각 상태를 정수 하나로 작게 표현할 뿐, 부분집합의 개수 자체를 줄이지 않는다. 모든 상태를 순회하는 알고리즘의 시간 복잡도는 여전히 `O(2ⁿ)`이다.

Java `int`는 32비트이고 `long`은 64비트다. 표현하려는 상태 수가 한 정수의 비트 폭을 넘으면 하나의 `int`나 `long`만으로 관리할 수 없다. `long`에서 비트를 선택할 때는 `1 << i`가 아니라 `1L << i`를 사용한다.

부호 비트와 Java의 시프트 거리 처리까지 고려하면 32개 또는 64개의 비트를 모두 일반적인 양의 정수 상태로 다루면 안 된다. 상태의 범위와 자료형을 함께 확인한다.

### 3.6 BitMask가 항상 더 좋은 자료구조는 아니다

BitMask는 작은 고정 집합이나 부분집합 상태처럼 원소 수와 인덱스 범위가 분명할 때 적합하다. 반면 원소가 동적으로 추가되거나 ID의 범위가 크고 실제로 사용하는 값이 듬성듬성하다면 `HashSet`이 더 적합하다.

| 상황 | 선택지 | 이유 |
| --- | --- | --- |
| 작은 고정 상태 집합 | BitMask | 정수 하나로 포함 여부와 조합을 표현한다. |
| 인덱스별 상태를 읽기 쉽게 관리 | `boolean[]` | 배열 인덱스가 상태 위치와 직접 대응한다. |
| 큰 값 범위와 동적 집합 | `HashSet` | 큰 ID를 비트 위치로 다시 매핑하지 않아도 된다. |

실제 서비스의 영구 데이터 저장까지 raw 비트마스크로 바꾸는 것이 항상 좋은 선택은 아니다. SQL에서 특정 상태를 조회하거나 의미를 확인하기 어렵고, 상태가 추가될 때 스키마와 해석 규칙도 함께 관리한다. 애플리케이션의 작은 고정 상태에는 BitMask를 검토할 만하지만, 동적인 사용자 ID 집합은 `Set`이나 관계형 구조가 더 읽기 쉬운 경우가 많다.

## 4. 오늘 배운 두 상태를 이전 학습과 연결하기

Dijkstra는 DFS/BFS처럼 그래프의 정점을 따라간다. 다음 정점을 고르는 기준이 다르다.

- DFS: 한 경로를 깊게 내려가는 순서
- BFS: Queue에 들어온 순서와 레벨
- Dijkstra: 현재까지의 누적 거리가 가장 짧은 정점

모든 간선의 가중치가 같다면 BFS로 최소 간선 수의 경로를 구한다. 가중치가 달라지면 방문 순서만으로 비용을 비교할 수 없어 Dijkstra처럼 거리를 상태로 저장한다.

BitMask는 Dynamic Programming과도 연결된다. DP는 계산한 상태를 저장하고 다시 사용한다. BitMask는 그 상태 중 “어떤 원소를 방문했는가”처럼 작은 집합을 정수 하나로 표현한다. 둘은 같은 개념이 아니지만 DP의 상태를 설계할 때 BitMask를 상태의 일부로 넣을 수 있다. 이번 학습에서는 이 연결만 확인하고 복잡한 비트마스크 DP 구현은 다루지 않았다.

## 5. Java 코드에서 확인할 기준

Dijkstra 코드를 읽을 때는 다음 항목을 점검한다.

1. `dist[start] = 0`, 나머지는 INF로 초기화했는가?
2. PQ 항목에서 정점 번호와 거리를 올바른 인덱스로 꺼내는가?
3. 오래된 항목을 `currentDist > dist[current]`로 건너뛰는가?
4. 완화에서 `dist[0]`이 아니라 `dist[current]`를 사용하는가?
5. 새 거리가 더 작을 때만 `dist[next]`와 PQ를 갱신하는가?

BitMask 코드는 선택 마스크와 실제 상태를 나눠 읽는다.

```java
int flag = 1 << i;                   // 선택할 비트
mask |= flag;                        // 켜기
mask &= ~flag;                       // 끄기
boolean exists = (mask & flag) != 0; // 확인
mask ^= flag;                        // 반전
```

`flag`를 만든 것만으로 `mask`가 바뀌지는 않는다. 기존 상태에 어떤 연산자를 적용하는지가 실제 상태 변화를 결정한다.

## 6. 오늘의 정리

Dijkstra는 하나의 시작 정점에서 각 정점까지의 누적 비용을 `dist`에 저장하고, 현재 거리가 가장 짧은 후보를 먼저 처리한다. 간선 완화는 새 비용이 기존 거리보다 작을 때만 일어난다. 음수 가중치가 있으면 최단 거리 확정을 보장할 수 없으므로 일반적인 다익스트라의 전제를 확인한다.

희소 그래프에서는 실제 간선만 저장하는 인접 리스트와 거리 기준 우선순위 큐를 조합한다. 큐에 오래된 항목이 남는 구현에서는 `currentDist > dist[current]`인 항목을 건너뛴다. 이때 현재 정점과 시작 정점을 혼동하지 않고 `dist[current]`를 사용하는 것이 핵심이다.

BitMask는 정수의 각 비트에 집합 원소의 포함 여부를 대응한다. `1 << i`는 선택 마스크이고, 추가는 OR, 삭제는 AND와 NOT, 확인은 AND, 반전은 XOR를 사용한다. 고정 폭 정수에서 단일 비트 연산은 `O(1)`이지만 모든 부분집합을 탐색하는 비용 `O(2ⁿ)`이 없어지지는 않는다.

이번 학습에서 알고리즘 이름보다 더 중요했던 것은 다음 상태를 정하는 기준을 분리한 일이다. Dijkstra는 누적 거리로 다음 정점을 고르고, BitMask는 선택한 비트와 기존 상태를 연산해 다음 mask를 만든다. 상태의 의미를 먼저 정하면 코드 한 줄의 역할도 따라가기 쉬워진다.
