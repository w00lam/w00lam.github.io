[Binary Search와 Hash Table](/posts/binary-search-hash-table/)을 정리하면서 정렬된 범위를 줄이거나 키로 버킷을 찾는 방법을 살펴봤다. 오늘은 자료구조의 상태가 달라지는 두 알고리즘을 이어서 공부했다. 그래프에서는 정점을 어떤 순서로 방문하는지 확인했고, 배열에서는 원래 순서를 유지하면서 가장 긴 증가 부분 수열을 찾는 방법을 정리했다.

DFS/BFS와 LIS는 같은 원리로 묶을 수 있는 알고리즘이 아니다. DFS와 BFS는 그래프를 탐색하는 순서와 자료구조의 차이가 핵심이고, LIS는 배열의 인덱스 순서를 지키면서 가능한 길이를 계산하는 문제다. 학습 기록에서도 두 주제를 따로 다뤘기 때문에 오늘 글도 각각의 상태 변화에 집중한다.

## 1. DFS와 BFS — 그래프를 어떤 순서로 방문할까

### 1.1 그래프와 인접 리스트

그래프는 정점(Vertex)과 정점 사이를 연결하는 간선(Edge)으로 표현한다. 연결 방향에 따라 방향 그래프와 무방향 그래프로 나뉜다. 방향 그래프의 간선은 한쪽 방향만 기록하지만, 무방향 그래프의 간선은 양쪽 정점에서 서로를 볼 수 있어야 한다.

예를 들어 1과 3을 무방향으로 연결한다면 인접 리스트에는 두 줄을 기록한다.

```java
graph.get(1).add(3);
graph.get(3).add(1);
```

첫 줄은 1에서 3으로 갈 수 있다는 뜻이고, 두 번째 줄은 3에서 1로 돌아갈 수 있다는 뜻이다. 한 줄만 추가하면 코드가 무방향 간선처럼 보이더라도 실제 탐색에서는 한쪽 방향만 확인하게 된다.

`List<List<Integer>> graph`에서 바깥 리스트는 정점별 인접 리스트를 담고, 안쪽 리스트는 해당 정점과 직접 연결된 이웃을 담는다. 정점 번호를 1부터 4까지 사용한다면 인덱스 0을 비워 두고 5개의 리스트를 만드는 예시를 생각할 수 있다. 인접 정점을 작은 번호부터 처리하려면 리스트에 넣는 순서도 방문 순서에 영향을 준다.

방문 배열도 필요하다.

```java
boolean[] visited = new boolean[graph.size()];
visited[current] = true;
```

방문 배열이 없으면 사이클이 있는 그래프에서 같은 정점을 계속 따라갈 수 있다. 무방향 그래프의 1과 3이 서로를 가리킬 때 1에서 3으로 이동한 뒤 다시 1로 돌아가는 일이 대표적이다. `visited`는 이미 처리한 정점을 다시 탐색하지 않도록 막는 상태다.

인접 행렬은 이번 학습에서 상세 구현까지 다루지 않았다. 오늘은 정점마다 이웃 목록을 순회하는 인접 리스트를 기준으로 DFS와 BFS를 살펴봤다.

### 1.2 DFS는 한 경로를 끝까지 내려간다

DFS(Depth-First Search)는 한 경로를 가능한 한 깊게 탐색한 뒤 더 진행할 수 없으면 이전 정점으로 돌아간다. 다음 그래프에서 인접 정점을 작은 번호부터 처리한다고 하자.

```text
       1
      / \\
     2   3
    / \\
   4   5
```

DFS의 방문 순서는 다음과 같다.

`1 → 2 → 4 → 5 → 3`

처음에는 `2 → 4 → 5 → 3`이라고 답해서 시작 정점 1을 빠뜨렸다. 시작 정점도 방문 순서에 포함해야 한다는 점을 다시 확인한 뒤 흐름을 단계별로 나눴다.

1. 1을 방문한다.
2. 1의 첫 번째 미방문 이웃 2로 이동한다.
3. 2의 첫 번째 미방문 이웃 4로 이동한다.
4. 4에서 더 진행할 정점이 없어 2로 돌아온다.
5. 2의 다음 이웃 5를 방문한다.
6. 2의 탐색이 끝나 1로 돌아온다.
7. 1의 다음 이웃 3을 방문한다.

재귀 DFS는 다음처럼 현재 정점을 방문 처리한 뒤 이웃을 순회하고, 방문하지 않은 정점에서 다시 `dfs`를 호출한다.

```java
static void dfs(int current) {
    visited[current] = true;
    for (int next : graph.get(current)) {
        if (!visited[next]) {
            dfs(next);
        }
    }
}
```

`dfs(4)`가 끝나면 프로그램이 처음부터 다시 시작하는 것이 아니다. `dfs(4)`를 호출했던 이전 `dfs(2)`의 반복문으로 돌아간다. 호출 Stack에 남아 있던 `dfs(2)`가 다음 인접 정점 5를 확인하는 흐름이다. 재귀 호출이 어떤 순서로 쌓이고 종료되는지 따라가야 복귀 지점을 놓치지 않는다.

재귀 대신 `Deque`를 Stack처럼 사용할 수도 있다.

```java
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1);
while (!stack.isEmpty()) {
    int current = stack.pop();
    if (visited[current]) continue;
    visited[current] = true;
    for (int next : graph.get(current)) {
        if (!visited[next]) stack.push(next);
    }
}
```

이 예시는 `pop`한 시점에 방문 처리한다. 그래서 같은 정점이 아직 방문 처리되기 전에 Stack에 여러 번 들어갈 수 있고, `pop` 직후의 `visited` 검사로 중복 처리를 건너뛴다. 또 Stack은 LIFO이므로 이웃을 push하는 순서에 따라 재귀 DFS와 방문 순서가 달라질 수 있다. `[2, 3]`을 그 순서로 push하면 다음 `pop`은 3이다. 재귀 DFS와 같은 순서를 만들려면 push 순서를 반대로 조정해야 할 수 있다.

### 1.3 BFS는 가까운 정점부터 확인한다

BFS(Breadth-First Search)는 Queue를 사용해 시작 정점에서 가까운 정점부터 탐색한다. Queue는 먼저 들어온 원소를 먼저 꺼내는 FIFO 구조다.

앞의 그래프에서 시작 정점 1을 방문한다고 하자.

```text
초기:       [1]
1을 poll:   []
2, 3 offer: [2, 3]
2를 poll:   [3]
4 offer:    [3, 4]
```

처음에는 1을 `poll`한 뒤에도 Queue에 1이 남아 있다고 생각했다. `poll`은 요소를 반환하면서 Queue에서 제거하므로 `[1] → []`가 맞다. 그다음 2와 3을 넣으면 `[2, 3]`이 되고, 2를 꺼낸 뒤에는 `[3]`이 남는다.

BFS에서는 보통 Queue에 넣는 순간 방문 표시를 한다.

```java
Queue<Integer> queue = new ArrayDeque<>();
queue.offer(1);
visited[1] = true;

while (!queue.isEmpty()) {
    int current = queue.poll();
    for (int next : graph.get(current)) {
        if (!visited[next]) {
            visited[next] = true;
            queue.offer(next);
        }
    }
}
```

방문 표시를 `poll`한 뒤로 미루면 같은 정점이 Queue에 들어가기 전에 다른 경로에서 다시 발견될 수 있다. 방문 배열이 존재한다는 사실만으로 중복 삽입이 자동으로 사라지는 것은 아니다. 이 학습에서는 Queue에 `offer`하는 시점에 `visited[next] = true`를 실행해 중복 삽입을 막는 흐름을 기준으로 정리했다.

다음 시각화에서 DFS의 재귀 호출 Stack과 BFS의 Queue를 같은 그래프 위에서 비교할 수 있다. 모드를 바꾸면 해당 방식의 초기 단계로 돌아가며, 이전·다음·초기화 버튼과 방향키로 상태를 이동할 수 있다.

### 1.4 BFS와 최단 거리

가중치가 없는 그래프에서 최소 이동 횟수, 즉 최소 간선 수를 구할 때는 BFS가 자연스럽다. Queue에 들어간 정점은 시작 정점에서 거리 0인 층, 거리 1인 층, 거리 2인 층의 순서로 처리된다. 가까운 정점을 먼저 발견하므로 어떤 정점을 처음 발견했을 때의 거리가 최소 간선 수가 된다.

거리 배열은 다음처럼 갱신한다.

```java
distance[next] = distance[current] + 1;
```

시작 정점에서 2를 한 번의 간선으로 발견했다면 `distance[2] = 1`이다. 2에서 4를 처음 발견하면 `distance[4] = distance[2] + 1`, 즉 `2`가 된다.

학습 초반에는 최소 이동 횟수를 구하는 문제에 DFS를 선택했다. DFS는 한 경로를 깊게 들어가므로 먼저 도착한 경로가 가장 짧다고 보장할 수 없다. 다른 경로에 더 짧은 길이가 남아 있어도 현재 경로를 끝까지 확인한 뒤에야 돌아오기 때문이다. 가중치가 없는 그래프의 최소 간선 수는 BFS의 레벨 순서가 보장하는 성질과 연결해서 이해해야 한다.

이 설명은 간선마다 비용이 같다는 전제에서 성립한다. 간선 가중치가 서로 다른 일반적인 그래프에서 BFS가 항상 최소 비용 경로를 보장한다고 말할 수는 없다.

### 1.5 시간·공간 복잡도

인접 리스트에서 DFS와 BFS의 시간 복잡도는 모두 `O(V + E)`다. `V`는 정점 수, `E`는 간선 수다. 각 정점을 방문하고 각 정점의 인접 리스트에 있는 간선을 확인하므로 정점 처리와 간선 확인을 합쳐 `O(V + E)`가 된다.

인접 행렬에서는 정점 하나를 확인할 때마다 전체 행을 살펴볼 수 있어 `O(V²)`가 된다. 같은 DFS/BFS라도 그래프를 어떤 방식으로 표현했는지에 따라 간선 확인 비용이 달라진다.

방문 배열을 포함한 보조 공간은 최악의 경우 두 방식 모두 `O(V)`다. DFS는 재귀 호출 깊이나 Stack에 쌓이는 정점 수가 영향을 주고, BFS는 Queue에 대기하는 정점 수가 영향을 준다. 최악의 상한이 같다는 말이 실제 탐색 중 메모리 사용량까지 언제나 같다는 뜻은 아니다. 그래프 자체를 보관하는 인접 리스트의 `O(V + E)` 공간과 탐색 보조 공간도 구분해야 한다.

### 1.6 백엔드의 계층 데이터와 탐색 선택

조직 계층이나 연결된 데이터처럼 관계를 따라가야 하는 구조에서는 DFS와 BFS를 떠올릴 수 있다. 단계별로 가까운 부서부터 확인해야 한다면 BFS의 레벨 순서가 설명하기 쉽고, 연결된 모든 정점을 한 경로씩 깊게 확인하는 작업에는 DFS도 사용할 수 있다.

다만 단순한 부모 참조 체인이라면 BFS를 꺼내기보다 반복문으로 부모를 따라가는 편이 간단할 수 있다. 알고리즘을 적용했다는 사실보다 데이터의 관계와 필요한 결과를 먼저 봐야 한다. 이번 학습은 프로젝트에서 DFS나 BFS를 직접 구현한 경험이 아니라, 어떤 상황에서 탐색 순서를 선택할지 기준을 정리한 기록이다.

## 2. LIS — 원래 순서를 지키며 가장 긴 증가 부분 수열 찾기

### 2.1 LIS가 의미하는 것

LIS는 Longest Increasing Subsequence의 약자다. 배열의 원래 순서를 유지하면서 일부 원소를 건너뛸 수 있는 가장 긴 엄격한 증가 부분 수열을 뜻한다.

다음 배열에서는 `2 → 3 → 4 → 5`를 선택할 수 있다.

```text
[7, 2, 3, 8, 4, 5]
```

길이는 `4`다. 원소를 건너뛸 수 있지만 순서를 바꿀 수는 없다. `2 → 3 → 7 → 8`은 값만 보면 증가하지만 7이 배열의 앞쪽 인덱스에 있으므로 원래 순서를 위반한다. LIS는 정렬된 배열을 만드는 문제도 아니고, 연속된 원소만 고르는 문제도 아니다.

같은 값은 엄격한 증가 조건에서 연속으로 선택할 수 없다. `[1, 2, 2, 3]`의 LIS 길이가 3인 이유도 두 개의 2를 모두 연결할 수 없기 때문이다.

처음에는 작은 배열에서 LIS를 바로 찾지 못했다. 이후 원소를 건너뛰어도 인덱스가 앞으로만 이동하면 부분 수열이 된다는 점을 확인하면서, 값의 크기와 인덱스 순서를 함께 봐야 한다는 것을 이해했다.

### 2.2 DP 배열의 의미

DP 방식에서 가장 중요한 것은 `dp[i]`의 의미다.

`dp[i]`는 `arr[i]`에서 반드시 끝나는 LIS의 최대 길이다. `i`번째까지 확인한 전체 LIS 길이가 아니다. 그래서 전체 LIS 길이는 `dp` 배열의 마지막 값이 아니라 최댓값을 구해야 한다.

모든 원소는 자기 자신만으로 길이 1의 증가 부분 수열이 된다. 따라서 다음처럼 초기화한다.

```java
int[] dp = new int[n];
Arrays.fill(dp, 1);
```

`[7, 2, 3, 8, 4, 5]`에 대해 계산한 `dp`는 다음과 같다.

```text
dp = [1, 1, 2, 3, 3, 4]
```

예를 들어 `dp[4] = 3`인 것은 인덱스 4의 값 4에서 끝나는 `2 → 3 → 4`의 길이가 3이라는 뜻이다. `dp[5] = 4`는 `2 → 3 → 4 → 5`가 인덱스 5의 값 5에서 끝난다는 뜻이다. 전체 LIS 길이는 이 배열의 최댓값인 4다.

### 2.3 점화식과 비교 방향

현재 위치를 `i`, 그보다 앞선 위치를 `j`라고 하자. `j < i`이고 이전 값이 현재 값보다 작다면, `j`에서 끝나는 증가 부분 수열 뒤에 현재 원소를 붙일 수 있다.

핵심 조건은 다음과 같다.

```java
arr[j] < arr[i]
```

조건을 만족할 때 갱신한다.

```java
dp[i] = Math.max(dp[i], dp[j] + 1);
```

전체 반복문은 다음과 같은 형태다.

```java
for (int i = 0; i < n; i++) {
    for (int j = 0; j < i; j++) {
        if (arr[j] < arr[i]) {
            dp[i] = Math.max(dp[i], dp[j] + 1);
        }
    }
}
```

학습 과정에서 두 가지를 혼동했다. 처음에는 증가 조건을 `arr[i] < arr[j]`로 반대로 적었다. 또 `dp[j] < dp[i]`처럼 DP 배열의 길이를 비교해 증가 여부를 판단하려 했다. 수정한 이해는 간단하다.

- 실제 원소의 증가 여부는 `arr[j] < arr[i]`로 판단한다.
- 증가 부분 수열의 길이는 `dp[j] + 1`로 계산한다.
- 가능한 길이 중 최댓값을 `Math.max`로 유지한다.

반복문 범위에서도 `arr.length - 1`을 종료 조건처럼 사용해 마지막 원소가 빠지는 문제가 있었다. Java의 인덱스는 마지막 값이 `length - 1`이지만, 반복 조건은 `i < n` 또는 `i < arr.length`로 써야 마지막 인덱스까지 처리한다. `i < arr.length - 1`로 쓰면 i가 마지막 인덱스에 도달하지 않는다.

아래 시각화는 초기화부터 모든 `i`, `j` 비교와 `dp[i]` 갱신까지 단계별로 보여 준다. 비교 중인 원소, 증가 조건의 참·거짓, 현재 `dp` 값을 같이 표시하므로 `arr`와 `dp`를 혼동했던 지점을 다시 확인할 수 있다.

### 2.4 Binary Search로 처리 비용 줄이기

DP 방식은 각 `i`마다 앞선 `j`를 확인하므로 시간 복잡도가 `O(N²)`다. 내부 비교 횟수는 `0 + 1 + 2 + ... + (N - 1)`, 즉 `N(N - 1) / 2`로 볼 수 있다. 공간 복잡도는 `dp` 배열 때문에 `O(N)`이다.

더 큰 입력에서는 Binary Search를 이용하는 방식을 학습했다. 이때 사용하는 `tails`는 실제 LIS를 그대로 저장하는 배열이 아니다. `tails[k]`는 길이가 `k + 1`인 증가 부분 수열에서 가능한 최소 끝값을 관리한다.

예를 들어 다음 상태에서 새 원소 4를 처리하면

```text
tails = [2, 5]
```

5를 4로 교체해 다음 상태를 만든다.

```text
tails = [2, 4]
```

길이가 2인 증가 부분 수열의 끝값을 5보다 작은 4로 낮춰 두면, 이후 더 큰 원소를 연결할 가능성이 커진다. 이 교체는 현재 LIS 길이를 늘리지 않는다. 반대로 현재 가장 큰 끝값보다 큰 9가 들어오면 뒤에 추가한다.

```text
tails = [2, 4, 7]
새 원소 9 → [2, 4, 7, 9]
```

새 원소를 어디에 놓을지는 Lower Bound로 찾는다. Lower Bound는 target 이상인 첫 번째 위치다.

```text
tails  = [2, 4, 7, 9]
target = 5
결과   = index 2
```

따라서 7을 5로 교체한다. `tails[mid] < target`이면 mid와 그 왼쪽은 target 이상인 첫 위치가 될 수 없으므로 `left = mid + 1`로 범위를 줄인다. 그 외에는 `right = mid`로 더 왼쪽에 조건을 만족하는 위치가 있는지 확인한다.

이 방식으로 `[7, 2, 3, 8, 4, 5]`를 처리하면 상태는 다음처럼 변한다.

```text
7 → [7]
2 → [2]
3 → [2, 3]
8 → [2, 3, 8]
4 → [2, 3, 4]
5 → [2, 3, 4, 5]
```

최종 길이는 4다. 다만 `tails`가 실제 LIS 수열이라는 뜻은 아니다. 입력 `[2, 5, 3, 1]`을 처리하면 최종 `tails`가 `[1, 3]`이 될 수 있지만, `[1, 3]`은 원래 입력에서 순서를 지킨 부분 수열이 아니다. `tails`는 길이별 최소 끝값을 보관하는 상태 배열이다.

실제 LIS 수열을 복원하려면 추가적인 인덱스와 이전 원소 정보가 필요하다. 그 복원 알고리즘은 오늘 학습 범위에 없으므로 구현하지 않았다.

### 2.5 복잡도와 선택 기준

두 방식의 복잡도는 다음과 같다.

| 방식 | 시간 복잡도 | 공간 복잡도 | 상태 저장 방식 |
| --- | ---: | ---: | --- |
| DP | `O(N²)` | `O(N)` | 각 위치에서 끝나는 길이 `dp[i]` |
| Binary Search | `O(N log N)` | `O(N)` | 길이별 최소 끝값 `tails` |

DP는 각 위치에서 이전 원소를 직접 비교하므로 입력이 작고 구현을 따라가기 쉬울 때 선택할 수 있다. Binary Search 방식은 원소마다 Lower Bound 위치를 `O(log N)`에 찾기 때문에 입력이 커질수록 유리하다. 학습에서는 100개 원소라면 DP, 100,000개 원소라면 Binary Search 방식을 우선 검토했다. 이 숫자가 모든 문제의 절대적인 기준은 아니다. 입력 제한, 구현 검증 정도, 실제 요구사항을 같이 봐야 한다.

### 2.6 백엔드에서 LIS를 생각하는 범위

시간순 데이터에서 원래 순서를 유지하며 증가하는 구간의 최대 길이를 보고 싶다면 LIS를 후보로 생각할 수 있다. 예를 들어 날짜순 사용자 수에서 일부 날짜를 건너뛰더라도 증가하는 흐름이 얼마나 길게 이어지는지 확인하는 식이다.

다만 전일 대비 단순히 증가했는지만 확인하는 문제라면 인접 원소 비교가 더 단순하다. 날짜 필터링과 정렬은 데이터베이스가 담당하고, 필요한 데이터만 조회한 뒤 Java에서 LIS를 계산하는 식으로 역할을 나눌 수도 있다. 전체 데이터를 애플리케이션으로 가져오면 네트워크 전송량과 메모리 사용량이 커질 수 있으므로, 조회 범위부터 정하는 것이 중요하다.

이번 학습은 프로젝트에서 LIS를 구현하거나 성능을 측정한 기록이 아니다. 어떤 데이터가 LIS의 조건에 맞는지, DP와 Binary Search 중 어느 쪽을 검토할지 판단하는 기준을 정리했다.

## 3. 오늘의 정리

DFS는 한 경로를 깊게 탐색하고 더 진행할 수 없으면 이전 정점으로 복귀한다. 재귀 호출이나 Stack을 사용하며, 반복형 구현에서는 Stack의 push 순서와 방문 처리 시점을 함께 확인해야 한다.

BFS는 Queue의 FIFO 순서로 가까운 정점부터 탐색한다. `poll`한 정점은 Queue에서 제거되고, 중복 삽입을 막으려면 보통 `offer`하는 시점에 방문 표시를 한다. 가중치가 없는 그래프에서 최소 간선 수를 구할 때는 거리 배열과 BFS의 레벨 순서를 연결한다.

인접 리스트 기준 DFS와 BFS의 시간 복잡도는 `O(V + E)`이고, 방문 배열을 포함한 최악의 보조 공간은 `O(V)`다. 두 방식의 최악 상한이 같아도 DFS의 깊이와 BFS의 Queue 폭이 실제 상태에서 같다는 뜻은 아니다.

LIS는 원래 배열의 순서를 유지하면서 일부 원소를 건너뛸 수 있는 가장 긴 엄격한 증가 부분 수열이다. DP의 `dp[i]`는 `arr[i]`에서 끝나는 길이이고, `arr[j] < arr[i]`일 때 `dp[j] + 1`과 비교해 갱신한다. 전체 LIS 길이는 `dp` 최댓값이다.

Binary Search 방식의 `tails`는 길이별 최소 끝값을 관리한다. Lower Bound 위치의 값 교체는 길이를 늘리지 않지만 끝에 추가하면 길이가 1 증가한다. `tails`가 항상 실제 LIS를 뜻하지 않으며, 오늘은 수열 복원까지 다루지 않았다.

이번 학습에서 가장 중요했던 점은 알고리즘 이름을 외우는 것보다 각 자료구조가 현재 어떤 상태를 저장하고 다음 상태를 어떤 기준으로 정하는지 확인하는 일이었다. DFS는 호출 Stack, BFS는 Queue, LIS DP는 위치별 길이, Binary Search 방식은 길이별 최소 끝값을 저장한다. 같은 “탐색”이라는 단어가 있어도 상태의 의미가 다르면 다음 단계로 가는 규칙도 달라진다.
