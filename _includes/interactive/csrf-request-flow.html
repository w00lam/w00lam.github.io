로그인 정보가 Browser로 전달된다.

    사용자가 로그인하면 Browser가 대상 서버와의 인증 상태를 유지한다.

    인터랙티브 단계 초기화에 실패했다. 아래 단계 목록에서 CSRF 요청의 핵심 흐름을 확인할 수 있다.

    1. 1. 로그인

      사용자가 대상 서버에 로그인하고 Browser가 인증 상태를 맡는다.

      • 로그인 정보
      • Browser가 인증 Cookie를 저장한다.
    2. 2. 인증 상태 유지

      Browser는 대상 서버와 통신할 때 조건에 맞는 인증 Cookie를 전송할 수 있다.

      • 인증 Cookie
      • 공격자가 Cookie 값을 직접 읽어야 하는 것은 아니다.
    3. 3. 공격 페이지 방문

      로그인 상태의 사용자가 공격자가 준비한 페이지를 방문한다.

      • 상태 변경 요청 유도
      • 피해자의 Browser가 요청을 시작하도록 이용된다.
    4. 4. 대상 서버 요청

      Cookie 전송 조건이 충족되면 공격자가 만든 요청에도 인증 Cookie가 포함될 수 있다.

      • 상태 변경 요청
      • Cookie는 요청 조건에 따라 포함
      • SameSite 정책과 요청 조건에 따라 Cookie 전송 여부가 달라진다.
    5. 5. CSRF Token 검증

      보호 대상 요청은 유효한 CSRF Token이 있는지 확인한 뒤 처리 여부를 결정한다.

      • CSRF Token
      • Token 없음·불일치 → 보호 대상 요청 거부
      • 유효한 Token → 애플리케이션 정책에 따라 처리
