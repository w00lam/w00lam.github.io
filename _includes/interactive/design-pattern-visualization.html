    Responsibility comparison

    세 패턴이 분리하는 책임

    세 패턴 모두 변경을 다루지만, 분리하는 책임과 추가되는 복잡도는 서로 다르다.

    행위 패턴

    Template Method

    공통 실행 흐름↕변경되는 세부 동작

    상위 클래스가 순서를 고정하고 하위 클래스가 일부 단계를 구현한다.

    상속 관계가 깊어지고 결합도가 높아질 수 있다.
    생성 패턴

    Factory Method

    객체 생성→생성된 객체의 사용

    Creator의 공통 흐름과 ConcreteProduct 생성 책임을 나눈다.

    유형이 늘면 Creator와 Product 클래스도 늘어날 수 있다.
    행위 패턴

    Observer

    상태 변경→후속 작업

    Subject가 구체 구현체 대신 Observer 계약으로 여러 객체에 알린다.

    관찰자 목록과 알림 흐름을 추적하는 비용이 생긴다.

    패턴을 적용했다는 사실만으로 좋은 설계가 되지는 않는다. 변경 가능성, 결합도, 추적 비용, 유지보수성을 함께 비교해야 한다.

    Singleton 생성과 공유 상태

    생성 방식에 따라 가능한 실행 순서가 어떻게 달라지는지 비교한다.

    0단계 · instance = null 1 / 7
    Thread AA 대기
    Thread BB 대기
    공유 instance참조 없음모니터 사용 안 함
    생성된 객체
    #1 · 없음#2 · 없음
    실행 흐름두 Thread가 null을 확인할 수 있다.
    가능한 결과서로 다른 객체가 만들어질 수 있다.

    이 시각화는 가능한 실행 순서 중 하나를 보여 준다. 모든 실행에서 중복 생성된다는 뜻은 아니다.

    공유 상태 예시A가 0을 읽음 → B가 0을 읽음 → 최종 count = 1인스턴스 생성 보장과 `count++`의 원자성은 별개의 문제다.
